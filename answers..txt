# Ответы на вопросы по RESTful API Task Manager

## 1. HTTP коды состояния

- **Успешный GET**: 200 OK
- **Создание задачи (POST)**: 201 Created  
- **Запрос несуществующей задачи**: 404 Not Found

## 2. Идемпотентность методов

**Идемпотентные методы**: GET, PUT, DELETE

**Почему**: Повторные вызовы этих методов с теми же параметрами дают одинаковый результат состояния системы.

**Повторный DELETE**: 
- Если задача уже удалена, возвращает 204 No Content
- Если задача не существует, возвращает 404 Not Found
- Состояние системы после первого удаления не меняется при повторных вызовах

## 3. Преимущества Nginx перед прямым доступом к Flask

### Основные преимущества:

1. **Производительность**:
   - Nginx эффективно обрабатывает статические файлы
   - Кэширование ускоряет повторные запросы
   - Меньше нагрузки на Flask-приложение

2. **Безопасность**:
   - Скрывает внутреннюю структуру приложения
   - Легко настраивается SSL/TLS (HTTPS)
   - Защита от некоторых типов DDoS-атак

3. **Масштабируемость**:
   - Балансировка нагрузки между несколькими Flask-серверами
   - Можно обслуживать тысячи одновременных соединений

4. **Надежность**:
   - Проверка работоспособности бэкенд-серверов
   - Автоматический переход на резервные серверы при сбоях

5. **Дополнительные функции**:
   - Ограничение частоты запросов (rate limiting)
   - Перезапись URL
   - Сжатие данных (gzip)
   - Детальное логирование

### Краткое сравнение:

- **С Nginx**: Высокая производительность, хорошая безопасность, легко масштабируется
- **Без Nginx**: Подходит только для разработки, низкая производительность при высокой нагрузке

**Вывод**: Для production-среды всегда используйте Nginx перед Flask. Для разработки можно работать напрямую с Flask.
